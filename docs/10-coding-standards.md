# 编码规范（第二步生效）

## 语言与仓库

- 用户可见文案：中文。
- 代码标识符：英文。
- 不提交 `node_modules/`、`.env`、索引目录、操作系统垃圾文件。

## 结构

- 检索、LLM、UI 分模块，避免一个文件里完成「读盘 + 调模型 + HTML」。
- 知识解析集中一处，方便单测切块与 draft 过滤。

## 测试

- 切块、draft 过滤、路径穿越、无依据降级为 insufficient：必须有自动化测试。
- 不把真实 API Key 写进测试。

## 生成代码时

- 禁止引入与需求无关的脚手架（认证、管理后台、Docker 集群等），除非文档新增对应需求。
- 禁止把示例知识复制进源码字符串。
- 复杂逻辑旁用简短注释说明「对应哪个需求 ID」，不要写叙事性注释。
