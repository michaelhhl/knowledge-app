# 界面与交互

## 静态对照页

选定 Web 框架（实现计划 M0）之前，用仓库内 `prototype/index.html` 对照本文件核对布局、文案与状态。该页无后端、不安装依赖；知识浏览通过相对路径读取 `knowledge/`，不把知识正文复制进源码。用本地静态服务器打开时目录可渲染正文；直接用 `file://` 打开时正文可能无法读取，属预期。

## 页面

1. **问答**（默认首页）
   - 顶部：应用名「知识问答」
   - 主区域：对话流（问题 / 答案卡片）
   - 底部：多行输入 + 发送
   - 答案卡片：状态徽标（有依据 / 依据不足 / 已拒绝）、Markdown 正文、出处列表
2. **知识库**
   - 左侧或顶部：`_index.md` 目录
   - 右侧：渲染后的 Markdown
   - 明显标识 `draft`（若浏览实现包含草稿，默认不在此列出草稿）

## 交互规则

- 发送后输入框可清空或保留，由实现选一种并保持一致；推荐清空。
- 进行中禁用重复发送，显示「正在检索 / 正在生成」。
- 出处以链接展示 `title` 或 `file#heading`。
- 错误（网络、密钥缺失、索引未建）用横幅，不插入伪装成助手的假回复。
- 第一版浅色主题即可；中文字体回退系统字体栈。
- 布局：桌面优先，单栏在窄屏仍能完成提问。

## 文案

| 场景 | 文案 |
|------|------|
| 空知识库 | 知识库还没有已发布的文档。请在 knowledge/ 添加 Markdown。 |
| 未配置模型 | 未配置 LLM。请复制 .env.example 为 .env 并填写密钥。 |
| 依据不足 | 使用 `05-ai-qa-rules.md` 中的方向性文案，不要指责用户。 |

## 无障碍（P1）

- 发送按钮可键盘触发
- 焦点顺序合理
- 状态不要只靠颜色
