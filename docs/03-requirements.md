# 需求规格

状态约定：`P0` 第一版必须有；`P1` 第一版之后；`P2` 远期。

## 功能需求

| ID | 优先级 | 描述 | 验收要点 |
|----|--------|------|----------|
| FR-01 | P0 | 用户可在问答页输入自然语言问题并提交 | 空问题不可提交；有加载状态 |
| FR-02 | P0 | 系统仅基于 `knowledge/` 检索结果生成答案 | 单元/集成测试：库外事实不得出现在答案中 |
| FR-03 | P0 | 每条有依据的答案附带来源：相对路径 + 标题 | 点击可打开该文档；无来源不得呈现为确定事实 |
| FR-04 | P0 | 依据不足时返回固定类型的「无法回答」 | 文案符合 `05-ai-qa-rules.md`；仍可展示相近文档 |
| FR-05 | P0 | 支持查看知识库目录与单篇 Markdown 渲染 | 目录来自 `_index.md` 与文件树约定 |
| FR-06 | P0 | 提供「重建索引」或启动时自动索引 | 修改 Markdown 后，重建即可被检索到 |
| FR-07 | P0 | 展示最近一次问答的检索摘要（命中了哪些文件） | 开发/调试可关；默认对提问者可见文件名 |
| FR-08 | P1 | 多轮对话（同一会话最多保留 N 轮，默认 10） | 新会话可清空；追问能解析「这个」「上一份」 |
| FR-09 | P1 | 答案可复制；来源链接可复制 | |
| FR-10 | P1 | 简单反馈：有用 / 无用（仅本地记录） | 不上传除非用户明确配置 |
| FR-11 | P2 | 按标签、文件夹过滤检索范围 | |
| FR-12 | P2 | 多知识库切换 | 第一版仅一个 `knowledge/` 根 |

## 非功能需求

| ID | 优先级 | 描述 |
|----|--------|------|
| NFR-01 | P0 | 单机可运行；知识文件默认留在本地磁盘 |
| NFR-02 | P0 | 调用外部 LLM API 时，只发送问题、检索片段、系统规则，不发送无关文件 |
| NFR-03 | P0 | 配置（API Key 等）来自环境变量或本地配置文件，不提交到 git |
| NFR-04 | P0 | 索引与回答失败要有可读错误，不得用假答案顶上 |
| NFR-05 | P1 | 知识库在约 500 篇、每篇约 2000 字量级时，检索 + 首包在常见网络下可接受（目标：检索 < 2s，不含模型耗时） |
| NFR-06 | P1 | 日志不记录 API Key；默认不记录完整用户问题到远程 |
| NFR-07 | P0 | 界面与文档对中文内容一等支持 |

## 接口与配置（第二步实现时遵守）

- 知识根目录：仓库内 `knowledge/`，可用环境变量 `KNOWLEDGE_ROOT` 覆盖。
- HTTP API 根路径为 `/api`。
- API 错误响应至少包含稳定的机器可读 `code` 与面向用户的 `message`，并使用恰当的 HTTP 状态码。
- LLM：第一版不内置默认提供商；用户通过环境变量配置 `LLM_PROVIDER`、`LLM_MODEL` 与 `LLM_API_KEY` 后启用问答。
- 未配置 LLM 时，知识浏览、索引与检索仍可用；问答请求必须返回可读的配置缺失错误，不得生成假答案。
- 第一版提供 HTTP API + 一个 Web 前端即可，不必同时做桌面端与 CLI（CLI 为 P1）。

## 已决事项

- U-01：第一版不提供默认 LLM 提供商，但保留通过环境变量配置提供商的能力。
- U-02：第一版前端形态为本机 Web。
