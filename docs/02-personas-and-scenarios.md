# 人物与场景

## 人物

### P1 提问者

想快速得到「按我们文档该怎么做」的答案。不关心检索实现，关心对不对、能不能点开原文。

### P2 知识维护者

用编辑器改 `knowledge/` 下的 Markdown。希望约定简单：标题、标签、一份索引即可。

### P3 实现者 / 编码助手

根据 `docs/` 写程序。需要需求可验收、AI 行为可测试、知识格式稳定。

## 主场景

### S1 带着问题打开应用

1. 提问者进入问答页。
2. 输入问题，可选附加上下文（当前项目名、环境）。
3. 看到简短答案、条目化要点、以及出处列表。
4. 点击出处打开对应 Markdown 标题位置。

### S2 知识不够用

1. 模型判定依据不足。
2. 界面显示「知识库中没有足够依据」，可列出最接近的 1–3 篇文档标题。
3. 不编造步骤或政策。

### S3 维护者新增一篇知识

1. 按 `docs/04-knowledge-model.md` 新建 `.md`。
2. 更新 `knowledge/_index.md`（若该篇需要出现在目录中）。
3. 触发索引刷新（第二步实现；第一版可以是重启或手动「重建索引」）。
4. 用该篇能回答的问题做一次试问，确认被引用。

### S4 追问

1. 提问者基于上一轮继续问。
2. 系统保留最近若干轮对话，但仍只使用知识库 + 当前对话消歧，不引入库外事实。

## 反场景（必须避免）

- 把通用模型常识当成公司规定
- 合并多篇文档时不标明分别来自哪一篇
- 维护者改了 Markdown，问答仍引用旧内容且无过期提示
