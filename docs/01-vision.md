# 产品愿景

## 一句话

用户用自然语言提问，应用只根据本地 Markdown 知识库作答，并给出可点击的出处。

## 问题

团队知识散落在文档里，搜索关键词容易漏，问同事成本高。通用聊天模型又会编造、无法指向本仓库里的具体段落。

## 目标用户

内部使用优先：需要反复查阅同一套规范、流程、FAQ 的人。第一版不做公开社区、不做多租户 SaaS。

## 产品原则

1. **Markdown 是知识源。** 更新知识 = 更新 `.md` 文件。
2. **有据才答。** 答案必须能指向知识库中的文件与标题/段落。
3. **不知道就说不知道。** 禁止用模型训练数据填补本库没有的事实。
4. **本地可运行。** 第一版可在单机或内网部署，知识默认不上传到第三方做训练。
5. **文档驱动代码。** `docs/` 变更先于功能变更。

## 成功标准（第一版）

- 对 `knowledge/` 内已有主题，能给出正确、简短、带来源的回答。
- 对库外问题，明确拒绝并建议相关文档（若有）。
- 非技术人员能通过编辑 Markdown 增加知识，无需改代码。
- 从提问到首字回答可接受（见非功能需求）；失败时有明确错误，而不是假答案。

## 明确不做（第一版）

- 多用户权限体系、审核工作流、知识图谱可视化
- 自动爬取外网作为知识
- 语音、多模态图片理解（知识库内图片仅作附图，不参与回答依据）
- 让模型「自由发挥」写长文教程替代知识库
